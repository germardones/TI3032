2. Búsqueda Avanzada: Expresiones Regulares

Un operador de igualdad solo captura coincidencias exactas. Cuando necesitas buscar documentos donde un campo de texto empieza con, termina con o contiene un patrón específico, la herramienta correcta son las expresiones regulares (regex). MongoDB integra el motor de regex de PCRE (Perl Compatible Regular Expressions) directamente en sus filtros de búsqueda a través del operador $regex.

Dos Sintaxis Equivalentes

MongoDB acepta el patrón regex de dos formas. Ambas son funcionales; la notación de barra diagonal es más compacta, mientras que la forma con $regex permite agregar opciones de forma más legible.

Notación literal de regex (JavaScript):

db.productos.find({
  nombre: /teclado/i
})

Notación con operador $regex:

db.productos.find({
  nombre: {
    $regex: "teclado",
    $options: "i"
  }
})

Opciones de Regex: el parámetro $options

Opción Nombre Comportamiento
i Case Insensitive Ignora mayúsculas/minúsculas. "teclado" coincide con "Teclado", "TECLADO", "TeCLaDo".
m Multiline Los anchors ^ y $ coinciden con el inicio/fin de cada línea, no solo del string completo.
s Dotall El punto . coincide también con caracteres de nueva línea (\n), que normalmente no captura.
x Extended Ignora espacios en blanco y permite comentarios en el patrón regex para mejorar la legibilidad.

Patrones de Búsqueda más Comunes

Los tres patrones siguientes cubren el 90% de los casos de uso de texto libre en aplicaciones reales.

Comienza con (^)

El anchor ^ fija el inicio del string. Útil para buscar por prefijo, por ejemplo todos los códigos de producto que empiezan con "PRD".

// Productos cuyo nombre empieza con "Mac"
db.productos.find({ nombre: { $regex: "^Mac" } })

// Emails de dominio corporativo (ignorando mayúsculas)
db.usuarios.find({ email: { $regex: "^admin", $options: "i" } })

Termina con ($)

El anchor $ fija el final del string. Útil para buscar por extensión de archivo, dominio de email, sufijo en códigos, etc.

// Usuarios con email del dominio @empresa.cl
db.usuarios.find({ email: { $regex: "@empresa\\.cl$", $options: "i" } })

// Archivos con extensión .pdf
db.documentos.find({ archivo: { $regex: "\\.pdf$", $options: "i" } })

Contiene (sin anchors)

Sin ^ ni $, el patrón puede aparecer en cualquier posición. Es el equivalente del LIKE '%texto%' de SQL.

// Productos que contienen "inalámbric" en cualquier parte del nombre
db.productos.find({ nombre: { $regex: "inalámbric", $options: "i" } })

// Notas de soporte que mencionan "error" o "falla"
db.tickets.find({ descripcion: { $regex: "error|falla", $options: "i" } })

Comparación con SQL LIKE

Patrón SQL LIKE MongoDB $regex
Empieza con LIKE 'Mac%' { $regex: "^Mac" }
Termina con LIKE '%.cl' { $regex: "\\.cl$" }
Contiene LIKE '%texto%' { $regex: "texto" }
Sin distinción mayúsculas ILIKE (PostgreSQL) { $regex: "x", $options: "i" }

Regex con Clases de Caracteres y Cuantificadores

Las expresiones regulares completas permiten patrones más sofisticados usando clases de caracteres, cuantificadores y grupos.

// RUT chileno: 7-8 dígitos, guión, dígito o K
db.personas.find({
  rut: { $regex: "^[0-9]{7,8}-[0-9Kk]$" }
})

// Teléfono celular chileno: +569 seguido de 8 dígitos
db.contactos.find({
  telefono: { $regex: "^\\+569[0-9]{8}$" }
})

// Código de producto: 2 letras mayúsculas + 4 dígitos (ej: TI3032)
db.productos.find({
  codigo: { $regex: "^[A-Z]{2}[0-9]{4}$" }
})

Uso de Regex en el Aggregation Pipeline

Dentro de un pipeline, $regex se usa igual que en find() — dentro de una etapa $match.

db.productos.aggregate([
  {
    $match: {
      nombre: { $regex: "pro", $options: "i" }
    }
  },
  {
    $group: {
      _id: "$categoria",
      total: { $sum: 1 }
    }
  }
])

Advertencia de rendimiento: Una consulta con $regex sin ^ (sin anclar al inicio) realiza un collection scan: recorre todos los documentos. Para colecciones grandes esto puede ser lento. Si la búsqueda de texto es frecuente y el volumen es alto, considera usar un índice de texto completo con db.coleccion.createIndex({ campo: "text" }) y el operador $text.
