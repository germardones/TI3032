1. Búsqueda Simple: Filtros y Operadores Relacionales

Todo sistema de datos gira en torno a una pregunta central: ¿cómo encuentro exactamente lo que necesito? En SQL la respuesta es la cláusula WHERE. En MongoDB es el documento de filtro, el primer argumento de find(). La diferencia clave es que en MongoDB el filtro es un objeto JSON, lo que lo hace legible, componible y nativamente tipado.

Anatomía de una Consulta find()

find() acepta hasta dos argumentos: el filtro (qué buscar) y la proyección (qué campos devolver). Si ambos se omiten, retorna todos los documentos con todos sus campos.

db.coleccion.find(
  { /* filtro — obligatorio, {} trae todo */ },
  { /* proyección — opcional */ }
)

Filtro SQL:

SELECT nombre, edad
FROM empleados
WHERE departamento = 'TI'
AND sueldo >= 800000;

Filtro MongoDB:

db.empleados.find(
  { departamento: "TI", sueldo: { $gte: 800000 } },
  { nombre: 1, edad: 1, _id: 0 }
)

Igualdad Exacta — El Filtro más Simple

El caso más frecuente: buscar documentos donde un campo tiene un valor concreto. El objeto JSON actúa como "molde" y MongoDB devuelve los documentos que coincidan con todos los pares clave-valor que especifiques.

// Buscar todos los productos de categoría "electrónica"
db.productos.find({ categoria: "electrónica" })

// Múltiples condiciones de igualdad actúan como AND implícito
db.productos.find({ categoria: "electrónica", disponible: true })

Operadores Relacionales de Comparación

Cuando la igualdad exacta no es suficiente, se usan operadores de comparación. En MongoDB todos los operadores llevan el prefijo $ y se anidan dentro del valor del campo:

{ campo: { $operador: valor } }

Operador Significado Ejemplo Equivalente SQL
$eq Equal (igual a) { edad: { $eq: 30 } } edad = 30
$ne Not Equal (distinto de) { estado: { $ne: "inactivo" } } estado <> 'inactivo'
$gt Greater Than (mayor que) { precio: { $gt: 50000 } } precio > 50000
$gte Greater Than or Equal { stock: { $gte: 1 } } stock >= 1
$lt Less Than (menor que) { edad: { $lt: 18 } } edad < 18
$lte Less Than or Equal { calificacion: { $lte: 4.0 } } calificacion <= 4.0

Operadores de Inclusión: $in y $nin

Permiten verificar si el valor de un campo pertenece (o no) a un conjunto de valores. Son el equivalente del IN (...) de SQL y evitan escribir múltiples condiciones $or.

// Buscar productos de categoría "electrónica" O "computación"
db.productos.find({
  categoria: { $in: ["electrónica", "computación"] }
})

// Excluir productos con estado "suspendido" o "agotado"
db.productos.find({
  estado: { $nin: ["suspendido", "agotado"] }
})

Operadores Lógicos: $and, $or, $not, $nor

Permiten construir condiciones compuestas. $and es implícito cuando se listan múltiples campos en el mismo objeto, pero se necesita la forma explícita cuando se aplican varios operadores sobre el mismo campo.

// $and explícito — mismo campo con dos condiciones distintas
db.empleados.find({
  $and: [
    { sueldo: { $gte: 500000 } },
    { sueldo: { $lte: 1500000 } }
  ]
})

// $or — departamento "TI" O sueldo mayor a 2.000.000
db.empleados.find({
  $or: [
    { departamento: "TI" },
    { sueldo: { $gt: 2000000 } }
  ]
})

// $nor — ninguna de las condiciones debe cumplirse
db.empleados.find({
  $nor: [
    { estado: "inactivo" },
    { contrato: "temporal" }
  ]
})

Ejemplo Práctico Completo

Un escenario real: buscar empleados del área de TI con sueldo entre 600.000 y 1.800.000, que no estén en estado "suspendido", ordenados por sueldo descendente y mostrando solo nombre, departamento y sueldo.

db.empleados.find(
  {
    departamento: "TI",
    sueldo: { $gte: 600000, $lte: 1800000 },
    estado:  { $ne: "suspendido" }
  },
  { nombre: 1, departamento: 1, sueldo: 1, _id: 0 }
).sort({ sueldo: -1 })

/* Resultado (ejemplo):
[
  { nombre: "Daniela Rojas",  departamento: "TI", sueldo: 1750000 },
  { nombre: "Patricio Muñoz", departamento: "TI", sueldo: 1420000 },
  { nombre: "Sofía Castillo", departamento: "TI", sueldo:  980000 }
] */

Tip de rendimiento: Los filtros sobre campos indexados son órdenes de magnitud más rápidos. Siempre que una condición sea selectiva (filtra una fracción pequeña del total), considera crear un índice con db.coleccion.createIndex({ campo: 1 }).
