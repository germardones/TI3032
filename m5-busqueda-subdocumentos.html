3. Búsquedas en Subdocumentos y Arreglos

Uno de los poderes únicos de MongoDB frente a las bases relacionales es que los documentos pueden contener objetos anidados (subdocumentos) y listas (arreglos). Pero ese poder solo es aprovechable si sabemos consultarlos. Para ello MongoDB ofrece dos herramientas clave: la notación de punto para navegar la jerarquía y los operadores de arreglo para filtrar dentro de listas.

Datos de Referencia para los Ejemplos

Trabajaremos con esta colección pedidos que contiene subdocumentos e items en arreglo:

db.pedidos.insertMany([
  {
    _id: ObjectId("p001"),
    numero:  "ORD-2026-001",
    estado:  "enviado",
    cliente: {
      nombre: "Valentina Ríos",
      region: "Metropolitana",
      tipo:   "premium"
    },
    items: [
      { producto: "Teclado Mecánico", cantidad: 1, precio: 85000 },
      { producto: "Mouse Inalámbrico", cantidad: 2, precio: 20450 }
    ]
  },
  {
    _id: ObjectId("p002"),
    numero:  "ORD-2026-002",
    estado:  "pendiente",
    cliente: {
      nombre: "Patricio Muñoz",
      region: "Valparaíso",
      tipo:   "estándar"
    },
    items: [
      { producto: "Monitor 24\"", cantidad: 1, precio: 320000 }
    ]
  }
])

Notación de Punto — Acceso a Campos de Subdocumentos

La dot notation (notación de punto) es la forma de "navegar" dentro de un subdocumento anidado. Se escribe como una cadena entre comillas: "padre.hijo" o "abuelo.padre.hijo" para niveles más profundos.

// Buscar pedidos cuyo cliente sea de la región Metropolitana
db.pedidos.find({ "cliente.region": "Metropolitana" })

// Combinar filtro en subdocumento con filtro en campo raíz
db.pedidos.find({
  "cliente.tipo": "premium",
  estado: { $ne: "cancelado" }
})

// Operadores relacionales también funcionan con dot notation
db.usuarios.find({
  "direccion.codigo_postal": { $regex: "^750" }
})

Regla clave: Las rutas con dot notation siempre deben ir entre comillas dobles en el filtro JSON: "cliente.region". Sin comillas, MongoDB las interpretaría como dos campos separados y la consulta fallaría silenciosamente.

Coincidencia Exacta de Subdocumento Completo

Es posible hacer match con el subdocumento completo como un único valor. Esta forma requiere que el orden de los campos y todos los valores coincidan exactamente — si el documento tiene campos adicionales que no se incluyen en el filtro, no habrá match.

// Coincidencia exacta: el subdocumento debe tener exactamente estos campos en este orden
db.pedidos.find({
  cliente: {
    nombre: "Valentina Ríos",
    region: "Metropolitana",
    tipo:   "premium"
  }
})

// Recomendación: prefiere dot notation — es más flexible y resistente
db.pedidos.find({ "cliente.nombre": "Valentina Ríos" })

Búsquedas en Arreglos de Valores Simples

Cuando un campo es un arreglo de valores escalares (strings, números), MongoDB permite consultarlos directamente. Un filtro de igualdad sobre un campo de arreglo retorna los documentos donde el arreglo contiene ese valor.

db.productos.insertMany([
  { nombre: "Laptop Pro", etiquetas: ["portatil", "oferta", "nuevo"] },
  { nombre: "Escritorio",  etiquetas: ["oficina", "oferta"] },
  { nombre: "Mouse",       etiquetas: ["portatil", "inalámbrico"] }
])

// Busca docs donde el arreglo "etiquetas" contiene "oferta"
db.productos.find({ etiquetas: "oferta" })
// → Laptop Pro, Escritorio

// $all — el arreglo debe contener TODOS los valores indicados
db.productos.find({ etiquetas: { $all: ["portatil", "oferta"] } })
// → Solo Laptop Pro (tiene ambas etiquetas)

// $size — arreglos con exactamente N elementos
db.productos.find({ etiquetas: { $size: 2 } })
// → Escritorio, Mouse (ambos tienen 2 etiquetas)

$elemMatch — Filtrar Arreglos de Subdocumentos

Cuando el arreglo contiene subdocumentos (objetos), necesitamos que un mismo elemento del arreglo cumpla todas las condiciones simultáneamente. El operador $elemMatch garantiza esto. Sin él, cada condición se evalúa de forma independiente sobre el arreglo completo, lo que puede generar falsos positivos.

Sin $elemMatch — puede dar falsos positivos:

db.pedidos.find({
  "items.precio":    { $gte: 50000 },
  "items.cantidad": { $gte: 2 }
})
// Retorna doc si items[0].precio >= 50000
// Y items[1].cantidad >= 2
// aunque sean elementos distintos

Con $elemMatch — un solo elemento debe cumplir todo:

db.pedidos.find({
  items: {
    $elemMatch: {
      precio:   { $gte: 50000 },
      cantidad: { $gte: 2 }
    }
  }
})
// Retorna doc solo si existe un único
// item que tenga precio >= 50000
// Y cantidad >= 2 al mismo tiempo
// Ejemplo práctico: pedidos con al menos un item de Monitor con precio > 200.000
db.pedidos.find({
  items: {
    $elemMatch: {
      producto: { $regex: "Monitor", $options: "i" },
      precio:   { $gt: 200000 }
    }
  }
})

Notación de Punto sobre Arreglos de Subdocumentos

La dot notation también funciona para acceder a campos dentro de arreglos de subdocumentos. MongoDB evaluará la condición sobre cada elemento del arreglo y devolverá el documento padre si al menos uno cumple.

// Pedidos que tienen al menos un item con precio >= 80.000
db.pedidos.find({ "items.precio": { $gte: 80000 } })

// Pedidos con un item cuyo nombre contiene "Teclado"
db.pedidos.find({
  "items.producto": { $regex: "Teclado", $options: "i" }
})

Acceso por Posición en el Arreglo

Si necesitas consultar un elemento en una posición específica del arreglo, usa la notación "campo.indice" (índice basado en 0).

// Buscar pedidos donde el PRIMER item tenga precio mayor a 50.000
db.pedidos.find({ "items.0.precio": { $gt: 50000 } })

// Buscar pedidos donde el SEGUNDO item sea de cantidad 2
db.pedidos.find({ "items.1.cantidad": 2 })

Ejemplo Final: Consulta Combinada Multi-nivel

Un caso real complejo: encontrar pedidos enviados de clientes de la región Metropolitana que incluyan al menos un item con precio mayor a 70.000, mostrando solo número de pedido, nombre del cliente e items.

db.pedidos.find(
  {
    estado:           "enviado",
    "cliente.region": "Metropolitana",
    items: {
      $elemMatch: { precio: { $gt: 70000 } }
    }
  },
  {
    numero:          1,
    "cliente.nombre": 1,
    items:           1,
    _id:             0
  }
)

/* Resultado:
[
  {
    numero: "ORD-2026-001",
    cliente: { nombre: "Valentina Ríos" },
    items: [
      { producto: "Teclado Mecánico", cantidad: 1, precio: 85000 },
      { producto: "Mouse Inalámbrico", cantidad: 2, precio: 20450 }
    ]
  }
] */
Técnica Cuándo usarla Ejemplo
Dot notation Filtrar por un campo específico de un subdocumento "cliente.region": "RM"
$all Arreglo debe contener todos los valores dados { $all: ["a", "b"] }
$size Arreglo con exactamente N elementos { $size: 3 }
$elemMatch Un elemento del arreglo cumple múltiples condiciones { $elemMatch: { precio: { $gt: 0 } } }
