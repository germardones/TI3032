5. Seguridad Referencial e Implementación con PyMongo

En las bases de datos relacionales, las claves foráneas (foreign keys) garantizan que una fila no pueda referenciar a otra que no existe — el motor rechaza la operación con un error. MongoDB, como base de datos documental, no tiene este mecanismo nativo: puedes guardar cualquier ObjectId o valor en un campo de referencia sin que MongoDB verifique que existe el documento correspondiente. Esto es una decisión de diseño deliberada para ganar flexibilidad y rendimiento, pero traslada la responsabilidad de la integridad al nivel de la aplicación.

El Problema: Referencias Huérfanas

Sin control, es fácil crear inconsistencias. Los escenarios más comunes son:

Referencia a documento inexistente:

# Se inserta un pedido con cliente_id que no existe
pedidos.insert_one({
    "numero":     "ORD-2026-999",
    "cliente_id": ObjectId("000000000000000000000000")
    # MongoDB acepta esto sin error
})

Documento padre eliminado sin limpiar hijos:

# Se elimina el cliente sin borrar sus pedidos
clientes.delete_one({ "_id": cliente_id })
# Los pedidos de ese cliente quedan "huérfanos"
# con una referencia que ya no apunta a nada

Estrategia 1: Referencias vs. Subdocumentos Embebidos

La primera decisión de diseño es si los datos relacionados deben guardarse como referencia (almacenar solo el _id del otro documento) o como subdocumento embebido (copiar los datos dentro del mismo documento). Cada enfoque tiene implicaciones de integridad distintas.

Aspecto Referencia Subdocumento embebido
Integridad Riesgo de referencia huérfana Sin riesgo (dato copiado)
Actualizaciones Cambiar el original actualiza todo Cambiar el original NO afecta las copias
Consulta Requiere $lookup o segunda query Todo en una sola lectura
Ideal para Datos que cambian frecuentemente Datos estables o históricos

Estrategia 2: Validación Manual de Referencias en PyMongo

La forma más directa de garantizar integridad referencial es verificar la existencia del documento referenciado antes de insertar. La función auxiliar siguiente encapsula este patrón.

from pymongo import MongoClient
from bson import ObjectId

client   = MongoClient("mongodb://localhost:27017/")
db       = client["tienda"]
clientes = db["clientes"]
pedidos  = db["pedidos"]
productos = db["productos"]

def existe(coleccion, doc_id) -> bool:
    """Retorna True si el documento con ese _id existe en la colección."""
    return coleccion.count_documents({ "_id": doc_id }, limit=1) > 0

def crear_pedido(cliente_id: ObjectId, items: list) -> dict:
    # 1. Validar que el cliente existe
    if not existe(clientes, cliente_id):
        raise ValueError(f"Cliente {cliente_id} no existe")

    # 2. Validar que cada producto referenciado existe
    for item in items:
        pid = item.get("producto_id")
        if pid and not existe(productos, pid):
            raise ValueError(f"Producto {pid} no existe")

    # 3. Solo insertar si todas las referencias son válidas
    doc = {
        "cliente_id": cliente_id,
        "estado":     "pendiente",
        "items":     items
    }
    resultado = pedidos.insert_one(doc)
    return { "insertado": str(resultado.inserted_id) }

Estrategia 3: Validación de Esquema con JSON Schema

MongoDB permite definir un validador de esquema directamente en la colección usando el estándar JSON Schema. Esto garantiza integridad de tipos y campos obligatorios en el motor, sin depender de la capa de aplicación.

# Crear la colección con validación de esquema
db.create_collection("pedidos", validator={
    "$jsonSchema": {
        "bsonType":   "object",
        "required":   ["cliente_id", "estado", "items"],
        "properties": {
            "cliente_id": { "bsonType": "objectId" },
            "estado": {
                "bsonType": "string",
                "enum":     ["pendiente", "enviado", "cancelado"]
            },
            "items": {
                "bsonType": "array",
                "minItems": 1,
                "items": {
                    "bsonType": "object",
                    "required": ["producto_id", "cantidad", "precio"],
                    "properties": {
                        "producto_id": { "bsonType": "objectId" },
                        "cantidad":   { "bsonType": "int", "minimum": 1 },
                        "precio":    { "bsonType": "int", "minimum": 0 }
                    }
                }
            }
        }
    }
})

Límite importante: JSON Schema valida estructura y tipos, pero no puede verificar que un ObjectId apunta a un documento real en otra colección. Para eso siempre se requiere validación explícita en la aplicación (como la función crear_pedido del ejemplo anterior).

Estrategia 4: Eliminación en Cascada con PyMongo

En SQL, un ON DELETE CASCADE elimina automáticamente las filas hijas cuando se borra el padre. En MongoDB esto también debe implementarse en la aplicación. El patrón recomendado es usar una función que primero elimine los documentos dependientes y luego el documento padre.

from pymongo import MongoClient
from bson import ObjectId

client   = MongoClient("mongodb://localhost:27017/")
db       = client["tienda"]

def eliminar_cliente_en_cascada(cliente_id: ObjectId) -> dict:
    # 1. Verificar que el cliente existe antes de operar
    cliente = db.clientes.find_one({ "_id": cliente_id })
    if not cliente:
        raise ValueError(f"Cliente {cliente_id} no encontrado")

    # 2. Contar pedidos dependientes
    n_pedidos = db.pedidos.count_documents({ "cliente_id": cliente_id })

    # 3. Eliminar primero los documentos dependientes
    db.pedidos.delete_many({ "cliente_id": cliente_id })

    # 4. Eliminar el documento padre
    db.clientes.delete_one({ "_id": cliente_id })

    return {
        "cliente_eliminado": str(cliente_id),
        "pedidos_eliminados": n_pedidos
    }

Estrategia 5: Detección de Referencias Huérfanas

En sistemas existentes con datos históricos, es útil ejecutar una consulta de auditoría para detectar documentos que referencian IDs que ya no existen. El aggregation pipeline con $lookup es la herramienta ideal.

# Detectar pedidos cuyos cliente_id ya no existen en la colección clientes
pipeline = [
    {
        "$lookup": {
            "from":         "clientes",
            "localField":  "cliente_id",
            "foreignField": "_id",
            "as":           "cliente_doc"
        }
    },
    {
        "$match": {
            "cliente_doc": { "$size": 0 }  # array vacío = referencia rota
        }
    },
    {
        "$project": {
            "numero":     1,
            "cliente_id": 1,
            "_id":        0
        }
    }
]

huerfanos = list(db.pedidos.aggregate(pipeline))
if huerfanos:
    print(f"Se encontraron {len(huerfanos)} pedidos huérfanos:")
    for p in huerfanos:
        print(f"  · {p['numero']} → cliente_id: {p['cliente_id']}")
else:
    print("Sin referencias rotas.")

Transacciones Multi-documento

Desde MongoDB 4.0, las operaciones que afectan a múltiples documentos o colecciones pueden envolverse en una transacción ACID. Esto garantiza que si falla cualquier paso, todos los cambios se revierten — el mismo principio del commit/rollback de SQL.

from pymongo import MongoClient
from bson import ObjectId

client = MongoClient("mongodb://localhost:27017/")
db     = client["tienda"]

def transferir_pedido(pedido_id: ObjectId, nuevo_cliente_id: ObjectId):
    with client.start_session() as sesion:
        with sesion.start_transaction():
            # Verificar que el nuevo cliente existe (dentro de la transacción)
            if not db.clientes.find_one({ "_id": nuevo_cliente_id }, session=sesion):
                raise ValueError("Nuevo cliente no existe")

            # Actualizar la referencia en el pedido
            db.pedidos.update_one(
                { "_id": pedido_id },
                { "$set": { "cliente_id": nuevo_cliente_id } },
                session=sesion
            )
            # Si algo falla aquí, el update anterior también se revierte

Requisito: Las transacciones multi-documento requieren que MongoDB esté corriendo en un Replica Set (incluso uno de un solo nodo) o en un cluster compartido. En una instancia standalone sin replica set, las transacciones no están disponibles.

Resumen: Checklist de Integridad Referencial

Situación Solución recomendada Implementación
Insertar con referencia Verificar existencia antes de insertar count_documents({ "_id": id }) > 0
Eliminar documento padre Eliminar hijos primero (cascada manual) delete_many({ "padre_id": id })
Validar estructura del documento JSON Schema en la colección create_collection(..., validator={...})
Operaciones multi-colección Transacciones ACID client.start_session()
Auditoría de datos existentes Pipeline con $lookup y $size: 0 Script periódico de detección
