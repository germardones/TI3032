2. Codificación Basada en Componentes

El modelo mental central de React es dividir la interfaz en piezas independientes y reutilizables: los componentes. Cada componente encapsula su propio marcado, lógica y (opcionalmente) estilos. La UI completa no es más que un árbol de componentes anidados.

Props: Comunicación Padre → Hijo

Las props son el mecanismo para pasar datos de un componente padre a uno hijo. Son de solo lectura: el hijo nunca debe modificar sus propias props.

// Componente hijo — recibe props como parámetro
function TarjetaProducto({ nombre, precio, disponible }) {
  return (
    <div className="tarjeta">
      <h3>{nombre}</h3>
      <p>${precio.toFixed(2)}</p>
      <span>{disponible ? 'En stock' : 'Agotado'}</span>
    </div>
  );
}

// Componente padre — pasa los datos como atributos JSX
function App() {
  return (
    <div>
      <TarjetaProducto nombre="Teclado" precio={49.99} disponible={true} />
      <TarjetaProducto nombre="Mouse"   precio={29.99} disponible={false} />
    </div>
  );
}

Estado con useState

El estado es la memoria interna de un componente. Al llamar a la función actualizadora, React programa un re-renderizado y actualiza la UI automáticamente.

import { useState } from 'react';

function FormularioLogin() {
  const [email,    setEmail]    = useState('');
  const [password, setPassword] = useState('');
  const [error,    setError]    = useState(null);

  function manejarEnvio(e) {
    e.preventDefault();
    if (!email || !password) {
      setError('Completa todos los campos');
      return;
    }
    setError(null);
    // lógica de autenticación...
  }

  return (
    <form onSubmit={manejarEnvio}>
      <input value={email}    onChange={e => setEmail(e.target.value)}    placeholder="Email"    />
      <input value={password} onChange={e => setPassword(e.target.value)} placeholder="Password" type="password" />
      {error && <p style={{ color: 'red' }}>{error}</p>}
      <button type="submit">Ingresar</button>
    </form>
  );
}

Efectos con useEffect

useEffect permite ejecutar código con efectos secundarios (fetch de datos, suscripciones, manipulación del DOM) sincronizados con el ciclo de vida del componente.

import { useState, useEffect } from 'react';

function TituloDocumento({ titulo }) {
  useEffect(() => {
    document.title = titulo;          // efecto secundario
    return () => { document.title = 'App'; };  // limpieza al desmontar
  }, [titulo]);                        // se re-ejecuta solo si `titulo` cambia

  return <h1>{titulo}</h1>;
}
Dependencias de useEffect Comportamiento
useEffect(fn) — sin array Se ejecuta después de cada renderizado.
useEffect(fn, []) — array vacío Se ejecuta solo una vez al montar el componente.
useEffect(fn, [a, b]) Se ejecuta cuando a o b cambian.

Renderizado de Listas

Para renderizar colecciones, se usa Array.map(). Cada elemento debe tener una prop key única para que React identifique cambios eficientemente.

const productos = [
  { id: 1, nombre: 'Teclado',  precio: 49.99 },
  { id: 2, nombre: 'Monitor', precio: 299.99 },
];

function ListaProductos() {
  return (
    <ul>
      {productos.map(p => (
        <li key={p.id}>{p.nombre} — ${p.precio}</li>
      ))}
    </ul>
  );
}

Comunicación Hijo → Padre (Callbacks)

Para que un hijo notifique un evento al padre, el padre le pasa una función como prop. El hijo la invoca cuando ocurre el evento.

// Hijo
function BotonEliminar({ id, onEliminar }) {
  return <button onClick={() => onEliminar(id)}>Eliminar</button>;
}

// Padre
function App() {
  const [items, setItems] = useState([1, 2, 3]);

  function eliminar(id) {
    setItems(prev => prev.filter(i => i !== id));
  }

  return (
    <div>
      {items.map(id => (
        <BotonEliminar key={id} id={id} onEliminar={eliminar} />
      ))}
    </div>
  );
}

Regla de oro: Los datos fluyen hacia abajo (props), los eventos fluyen hacia arriba (callbacks). Este patrón unidireccional hace que la aplicación sea predecible y fácil de depurar.
