6. Buenas Prácticas de Desarrollo Seguro en SPA

Una SPA (Single Page Application) ejecuta toda su lógica en el navegador del usuario. Esto desplaza parte de la superficie de ataque al frontend, haciendo que la seguridad sea una responsabilidad compartida entre el equipo de backend y el de frontend. A continuación se revisan las amenazas más críticas y cómo mitigarlas en React.

1. Cross-Site Scripting (XSS)

XSS ocurre cuando un atacante inyecta código JavaScript malicioso que se ejecuta en el navegador de otro usuario. React protege automáticamente los valores que renderiza mediante escapado automático, pero existen excepciones peligrosas.

Vulnerable:

// dangerouslySetInnerHTML sin sanitizar
function Comentario({ texto }) {
  return <p dangerouslySetInnerHTML=
    {{ __html: texto }} />;
  // Si texto = '<img src=x onerror=alert(1)>'
  // ejecuta JavaScript del atacante
}

Seguro:

import DOMPurify from 'dompurify';

function Comentario({ texto }) {
  const limpio = DOMPurify.sanitize(texto);
  return <p dangerouslySetInnerHTML=
    {{ __html: limpio }} />;
}

Regla general: Nunca usar dangerouslySetInnerHTML con datos provenientes del usuario sin sanitizar. Preferir siempre el renderizado estándar de React ({variable}), que escapa automáticamente.

2. Gestión Segura de Tokens de Autenticación

Los tokens JWT o tokens de sesión son el objetivo principal de los ataques XSS. El almacenamiento importa tanto como la autenticación misma.

Almacenamiento Accesible por JS Riesgo XSS Riesgo CSRF
localStorage Sí Alto Bajo
sessionStorage Sí Alto Bajo
Cookie HttpOnly No Bajo Medio (mitigar con SameSite) 
// Configuración recomendada de cookie en el backend (Express.js)
res.cookie('token', jwt, {
  httpOnly: true,   // no accesible desde JS
  secure:   true,   // solo HTTPS
  sameSite: 'Strict', // mitiga CSRF
  maxAge:   3600000    // 1 hora
});

3. Validación de Inputs

Nunca confiar en los datos que llegan del usuario. La validación en el frontend mejora la UX, pero la validación real debe ocurrir en el backend.

// Validación con React + librería Zod
import { z } from 'zod';

const esquemaRegistro = z.object({
  email:    z.string().email('Email inválido'),
  password: z.string()
              .min(8, 'Mínimo 8 caracteres')
              .regex(/[A-Z]/, 'Debe incluir una mayúscula')
              .regex(/[0-9]/, 'Debe incluir un número'),
  nombre:   z.string().min(2).max(50)
});

function validarFormulario(datos) {
  const resultado = esquemaRegistro.safeParse(datos);
  if (!resultado.success) {
    return resultado.error.flatten().fieldErrors;
  }
  return null; // sin errores
}

4. Variables de Entorno y Secretos

Las claves de API y configuraciones sensibles nunca deben hardcodearse en el código fuente. En Vite, las variables de entorno que comienzan con VITE_ se exponen al bundle del cliente — solo deben contener datos no críticos.

# .env.local — NO subir al repositorio (.gitignore)
VITE_API_URL=https://mi-api.com
VITE_MAPAS_KEY=pk_publico_de_mapbox   # solo claves públicas aquí
// Acceso en React
const apiUrl = import.meta.env.VITE_API_URL;

// ❌ NUNCA hacer esto
const secretKey = "sk_live_abc123..."; // visible en el bundle público

5. Protección de Rutas

Las rutas privadas deben verificar el estado de autenticación antes de renderizar contenido sensible. El componente RutaProtegida es el patrón estándar en React Router.

import { Navigate, Outlet } from 'react-router-dom';
import { useAuth } from './hooks/useAuth';

function RutaProtegida() {
  const { autenticado, cargando } = useAuth();

  if (cargando)      return <p>Verificando sesión...</p>;
  if (!autenticado)  return <Navigate to="/login" replace />;

  return <Outlet />; // renderiza la ruta hija si está autenticado
}

Checklist de Seguridad en SPAs

Control Implementación
Prevenir XSS Usar JSX estándar; sanitizar con DOMPurify si se usa HTML raw
Almacenamiento seguro de tokens Cookies HttpOnly + Secure + SameSite=Strict
Validación de entradas Validar en frontend (UX) Y en backend (seguridad real)
No exponer secretos Solo VITE_ para datos públicos; claves privadas solo en backend
Proteger rutas privadas Componente RutaProtegida con verificación de sesión
Dependencias seguras npm audit periódico; usar dependabot o Snyk
Content Security Policy Configurar cabecera CSP en el servidor para restringir scripts

Principio fundamental: El frontend es código público — cualquier usuario puede leerlo. Toda lógica de negocio, autorización real y datos sensibles debe vivir en el backend. React se encarga de la experiencia, el servidor se encarga de la seguridad.
